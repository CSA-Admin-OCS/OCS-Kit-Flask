Accounts and sign-in

People sign in with a username and password. The browser gets a session for these pages and a token cookie for the API, and both stop working when the password changes.

Three roles

Every account is a {{ kit.roles.admin.label }} (runs the site), a {{ kit.roles.staff.label }} (day-to-day work) or a {{ kit.roles.member.label }} (everyone else, and the role new sign-ups get: {{ kit.roles[kit.signup_role].label }}).

Permissions

One file, permissions.json, says who may make each request, and a request it does not list is refused. Admins can change a level from the Permissions page, with no restart.

Features by kit

A kit is a preset list of features. A feature that is off answers 404 and keeps its data, so turning it back on loses nothing.

Try the API

Everything the pages do goes through the REST API under /api.

# what this backend is running
curl {{ api_base }}/api/kit

# sign in (the cookie is saved in "jar"), then ask who you are
curl -c jar -X POST {{ api_base }}/api/authenticate \
  -H 'Content-Type: application/json' -H 'X-Origin: client' \
  -d '{"uid": "your-uid", "password": "your-password"}'
curl -b jar {{ api_base }}/api/id
