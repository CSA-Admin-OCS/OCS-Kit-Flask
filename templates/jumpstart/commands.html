CommandWhat it does
python main.pyThe development server on FLASK_PORT (8587), in debug mode, without a reloader: restart it after changing Python code. Template changes show without a restart, route changes do not.
gunicorn main:appThe production server. The Docker image runs it through entrypoint.sh with 5 workers and 2 threads each, a 30 second timeout, bound to port 8587.
docker compose up -d --buildThe backend, the socket service and the code runner together. See {{ ref('deploy') }}.
./setup_and_run.shFirst-time setup for a laptop: creates the virtual environment, upgrades pip and installs requirements.txt, then states what to run next.
./run_backend.shActivates the virtual environment and runs python main.py.
./check_status.shChecks whether something is listening on port 8587 and whether the API answers.

CommandWhat it does
python -m features --listPrints the kits, the categories and every feature, with whether it is on right now. See {{ ref('kits') }}.
python -m features --checkValidates the catalog against the code; one problem per line, exit 1 if there are any. See {{ ref('catalog-file') }}.

python -m permissions --checkCompares permissions.json with the app's routes: routes in no list, and entries for routes that do not exist. Exit 1 on a problem. See {{ ref('permissions') }}.
python -m pytest testsThe tests. Install pytest first. See {{ ref('testing') }}.

Everything: it makes a rollback point, drops every table (including what admins saved on the pages), creates them again and seeds the starting data and one account per role. It asks first when there is data to lose. Details in {{ ref('data') }}.

VariableEffect
FORCE_YES=truedo not ask

{% endcall %} {% call section("Moving data to and from a server") %}
CommandWhat it does
python scripts/db_migrate-prod2sqlite.pySigns in as the admin account (ADMIN_UID and ADMIN_PASSWORD) on FLASK_BASE_URL, pulls every data type through the export routes, and loads it into the local SQLite database. It checks the row counts and exits non-zero if any table did not transfer completely.
python scripts/db_restore-sqlite2prod.pyThe other direction: pushes the local data to that server, with the same count check.

The admin settings tables are not part of this transfer (see {{ ref('data') }}).
