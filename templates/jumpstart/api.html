Send and expect JSON, with Content-Type: application/json on a body. Sign in once, then send the cookie the answer sets (POST /api/authenticate; curl -c jar saves it, curl -b jar sends it), or send the token in an Authorization header. From a browser on another site, the site's origin must be allowed (see {{ ref('cors') }}) and requests must include credentials.

{% call code() %}curl -c jar -X POST http://localhost:8587/api/authenticate \ -H 'Content-Type: application/json' -d '{"uid": "admin", "password": "123Qwerty!"}' curl -b jar http://localhost:8587/api/id{% endcall %}

Some scripts and examples also send X-Origin: client. The backend does not require or check it; it is a habit of the migration scripts.

The refusals of the permission check and the sign-in decorator share one shape, so a client can handle them in one place. Other errors carry at least a message. Do not parse the 404 body: both "this route does not exist" and "this feature is off" answer the same HTML page on purpose.

Without page the whole list is returned as an array. Most other lists are small and returned whole.
