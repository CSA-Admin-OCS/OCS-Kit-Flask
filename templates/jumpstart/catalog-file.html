{% endcall %} {{ topic("A feature") }} {% call section("Contents of a feature") %} {% call code() %}"social": { "name": "Social", "category": "general", "labels": ["user-content"], "description": "...", "setup": { "summary": "...", "settings": [ ... ], "steps": [ ... ], "verify": "..." }, "flask": { "blueprints": [ ... ], "models": [ ... ], "seed": [ ... ], ... } }{% endcall %}

category must be one of the categories and every label one of the labels; python -m features --check says so if not. setup is the guide an admin sees: a summary, the settings the feature needs, the manual steps, and how to verify it works. Each setting is {key, service, required, secret, help, get_it, example}: service says which piece reads it (flask, spring or pages), and only the ones for flask are reported by this backend, as configured or not. A secret setting's value is never shown, and an example is only shown for a non-secret one.

{% endcall %} {% call section("The keys of a feature's flask block") %}
KeyMeaning
blueprints"module:attribute" of the blueprints this feature owns. They answer 404 while the feature is off. A blueprint has exactly one owner.
uses_blueprintsblueprints owned by another feature that this one also needs (ai-grading uses the Gemini routes); served while either is on.
inactive_blueprintsowned but never registered (code kept, disabled in main.py).
modelsmodules with this feature's tables. Always imported, so the tables always exist.
seed"module:function" that creates reference data, never accounts. Run by db_init.py, and when an admin turns the feature on while its tables are empty.
seed_accountsfunctions that create accounts with known passwords. Run only by db_init.py, on a database with no users.
startupfunctions run when the app starts and when the feature is turned on.
admin_links{label, endpoint} entries for the Data menu, with an optional group that puts several into one sub-menu ("Web Security"). An endpoint must be in one of the feature's own blueprints.

Any other key in a flask block is an error. A feature with no Flask code, such as lessons, has empty lists.

{% endcall %} {{ topic("A kit") }} {% call section("Contents of a kit") %} {% call code() %}"education": { "name": "OCS Education", "description": "...", "features": ["core", "lessons", "code-runner", ...], "roles": { "admin": {"label": "Admin", "seed_uid": "admin"}, "staff": {"label": "Teacher", "seed_uid": "teacher"}, "member": {"label": "Student", "seed_uid": "student"} }, "signup_role": "member" }{% endcall %}

features is the preset. roles gives the three canonical roles their labels in this kit and the usernames of the accounts created for them. signup_role is the canonical role new sign-ups get. All three roles must be present, and the stored names do not change with the kit (they are in flask.roles).

{% endcall %} {{ topic("Keeping it valid") }} {% call section("Verification with python -m features --check") %}
  • the catalog has a core feature, and every category and label a feature names exists
  • every kit's feature list refers only to real features, and the roles line up with the canonical ones
  • every module a feature names imports, and every blueprint in api/ or hacks/ is claimed by exactly one feature (so new code cannot skip gating)
  • every admin link points into its own feature's blueprint and every setting names a key and a service
  • this copy has not drifted from the canonical catalog, when that is present next to the repository (it compares everything except the two Flask-only parts)

The tests run the same check. When it fails it prints the exact problem, one per line.
